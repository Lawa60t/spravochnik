## Генератор: голый Node, без зависимостей

Планировался Astro. От него пришлось отказаться по факту: `registry.npmjs.org` закрыт политикой окружения, в котором идёт работа (403), а обходить её нельзя. Вместо этого — `src/site/build.js`: читает `data/`, пишет `dist/`. Ни одной зависимости, сборка не требует интернета и не может протухнуть от чужого релиза.

Это не временный костыль, а нормальное решение для такого сайта: 421 страница, ноль интерактива на первом уровне, замороженный контент. Астровская польза здесь свелась бы к островам, а остров на третьем этапе — один рукописный файл (прототип это доказывает: 1299 строк, ноль сборки).

Шаблоны — обычные функции, возвращающие строку. Если Astro когда-нибудь понадобится, перенос механический: тело функции переезжает в `.astro`, данные и адреса остаются как есть.

```
src/site/
  build.js            сборка и проверки
  config.js           домен, почта, владелец — всё, что заполняется перед публикацией
  data.js             загрузка базы, индексы, слаги, обратные связи
  text.js             ВСЕ строки, которые пишет сайт (их проверяет линт)
  meta.js             шаблоны title и description
  layout.js           каркас страницы
  pages/              статья, раздел, указатель, области, главная, служебные
  assets/style.css    один файл, системные шрифты
  assets/search.js    фильтр указателя
  assets/utochnenie.js  остров уточнения

src/engine.js         движок: Node и браузер, один файл
src/engine-data.js    чтение data/ для Node — весь шов целиком
src/questions-sex.json  вопросы не тому полу, решено вручную
```

## Адреса

Слаг — id с точкой, заменённой на дефис: точка в пути читается частью хостингов как расширение файла. Обратимость и отсутствие коллизий проверяются на сборке.

| Адрес | Что | Сколько |
|---|---|---|
| `/` | Главная: предупреждение, «что этот сайт не делает» | 1 |
| `/sostoyaniya/<статья>/` | Статья о состоянии | 307 |
| `/razdely/<раздел>/` | Раздел справочника | 110 |
| `/ukazatel/` | Алфавитный указатель со синонимами и списком разделов | 1 |
| `/chto-ne-razbiraem/` | `redflags.json` → `notSearchedHere` | 1 |
| `/moego-sluchaya-net/` | `redflags.json` → `noMatch` | 1 |
| `/oblasti/` | Области тела | 1 |
| `/oblasti/<зона>/` | Разделы области по участкам | 10 |
| `/zhaloby/` | Жалобы, которые нельзя показать пальцем | 1 |
| `/dannye/<раздел>.js` | Данные уточнения, грузятся по кнопке | 110 |
| `/telo/` | Фигура | этап 4 |
| `/o-spravochnike/`, `/kak-sostavleny/`, `/soglashenie/` | Служебные | до запуска |

Адрес всегда заканчивается слэшем, на диске это `index.html` — работает на любом статик-хостинге без правил переписывания.

**Ни ответ уточнения, ни поисковый запрос не попадает в адрес.** Никаких `?q=`, `?a=`. Запрос вроде «кровь в стуле» в адресной строке уходит в историю браузера и в логи хостинга, а на главной напечатано, что мы ничего не собираем. Логи хостинга с адресами страниц при этом остаются — это свойство веба, и заявление на главной сформулировано так, что остаётся правдой: мы не сохраняем **ответы**.

## Страницы

**Статья.** Плашка → название → МКБ → `alt` как «Также называют» → ограничения по полу и возрасту → пять полей базы подписями из прототипа («Что это», «У кого встречается чаще», «Когда бывает неотложным», «С этим идут к», «Чем обычно подтверждают») → **«В каких разделах справочника встречается»** → источник текстом, дата, видимый статус `compiled` → «здесь ошибка».

Блок обратных ссылок — то, что отличает энциклопедию от вывода опроса: 248 статей из 307 выходят в несколько разделов, и это видно на странице.

**Раздел.** Название, `aka`, затем **весь** список состояний раздела тремя блоками:

| Блок | Что попадает |
|---|---|
| Редко, но важно не пропустить | `redflag: true`, независимо от частоты |
| Встречается часто | `base` ≥ 5 |
| Встречается реже | `base` < 5 |

Порядок — по `base`, то есть по частоте состояния **в этом разделе**, а не по совпадению с читателем. Граница 5 выбрана по данным: при ней пустая группа возникает лишь в 7 разделах из 110.

Усечение из `present()` (первые 4 и следующие 5) сюда **не переносится**: это свойство выдачи после уточнения, а не оглавления. В разделах до 15 состояний, и если часть из них доступна только через опрос, справочник превращается в программу, выдающую заключение.

Ниже — `notSearchedHere` этого раздела и ссылка «моего случая здесь нет».

**Указатель.** Все 307 статей по алфавиту, синонимы из `alt` — отдельными строками с отсылкой «см.», как в книге. Ниже все 110 разделов с `aka`. Это и есть поиск первого уровня: без JavaScript человек находит статью здесь.

**Главная.** Предупреждение показано обычным блоком, а не модальным окном: модалка с запоминанием флажка — это уже JavaScript. Кнопка «Понятно» — честная ссылка на указатель, а не имитация согласия.

## title, description, канонический адрес

Один плохой шаблон — это 307 нарушений сразу, и именно он виден в поисковой выдаче, где нет ни плашки, ни подвала, ни контекста. Поэтому линт формулировок проверяет собранные `title` и `description` **в первую очередь**.

| Страница | title | description |
|---|---|---|
| Главная | `Справочник о теле — энциклопедия состояний` | фиксированное |
| Статья | `{название}: как проявляется · Справочник` | первое предложение поля «что это» + «Справочная статья: у кого встречается, когда бывает неотложным, к какому врачу» |
| Раздел | `{название} — раздел справочника` | `{название}: N состояний, при которых так бывает. Раздел справочника — что это, у кого встречается чаще, к какому врачу` |
| Указатель | `Алфавитный указатель · Справочник о теле` | сколько статей и разделов, открывается без уточнений |
| Служебные | `{заголовок} · Справочник о теле` | по смыслу страницы |

Назначение объявлено в каждом заголовке — слово «справочник» стоит в title всех 421 страницы. Ни «симптомы», ни «причины», ни «диагностика», ни «лечение» в шаблонах не встречаются.

Хвост шаблона держим коротким: линт меряет не длину title, а **накладные расходы** — `title` минус заголовок страницы, не больше 30 символов. Длинное название болезни это данные, их не сократить; раздутый хвост это наше, и в выдаче обрезается первым. Description обрезается по границе слова на 160 символах.

Канонический адрес — `origin` + путь, на каждой странице. `origin` живёт в `src/site/config.js` в единственном экземпляре; пока там заглушка, сборка ругается на каждом прогоне.

## sitemap.xml и robots.txt

Собираются вместе со страницами. В `sitemap.xml` все 421 адрес с `lastmod` из полей `updated` самой базы — у статьи своя дата, у раздела своя. `robots.txt` открывает всё и указывает на sitemap.

Полный каталог, доступный поисковику без опроса и без модели, — это ещё и правовая позиция: именно он отличает энциклопедию от программы, выдающей заключение.

Оба файла содержат абсолютные адреса, то есть публиковать их с заглушкой вместо домена нельзя.

## Хостинг — решить до публикации

Два жёстких критерия:

1. **Не ставит собственных кук.** На главной напечатано «не использует файлы cookie». Куки ставит не только счётчик: их ставят CDN, защита от ботов, A/B-функции хостинга. Ложное утверждение о приватности хуже отсутствующего.
2. **Доступен из России.** Читатель проекта — человек, которому плохо. Сайт, который у половины не открывается, не работает вообще.

Проверять эмпирически, а не по документации: открыть собранный сайт на выбранной площадке, в инструментах разработчика убедиться, что список кук пуст и **ни одного** запроса на чужой домен нет. Из этой сессии проверить невозможно.

Направление: российский VPS или статический хостинг с собственным nginx — доступность гарантирована, поведение кук под полным контролем. Зарубежные Pages-платформы отпадают по второму критерию раньше, чем по первому.

Решение за владельцем: оно связано с оплатой, доменом и сведениями в подвале.

Пятнадцать разделов в участках своей области не встречаются (тошнота, кровь в стуле, головокружение, боль внизу живота у женщин): они собраны в группу «не привязано к участку на фигуре». Без неё часть оглавления была бы доступна только с фигуры, которой ещё нет. Проверено: все 110 разделов достижимы со страниц областей.

`/zhaloby/` — вход `symptom.list`, 14 разделов.

## Поиск

Планировался индекс отдельным JSON. Оказалось не нужно: все 500 строк указателя уже отрисованы в HTML, и скрипт просто прячет лишние. Нет ни второго запроса, ни дублирования данных, а без JavaScript страница остаётся полным алфавитным списком.

Поле поиска **создаёт скрипт**. Без него поля просто нет — не появляется мёртвый элемент, который никуда не ведёт. Нормализация: регистр, ё→е, пунктуация; несколько слов — все должны найтись. Запрос **не попадает в адрес**: ни `?q=`, ни `localStorage`.

Русского текста в `search.js` нет: строки приходят из разметки атрибутами, чтобы оставаться под линтом формулировок.

Проверено в headless-браузере на настоящей собранной странице: поле создаётся, «ЖЁЛЧ» находит «Желчную колику», «ангина» находит отсылку к «Острому тонзиллиту», «остр тонзил» работает как два слова, пустой результат показывает подсказку со ссылкой «моего случая здесь нет».

## Уточнение и движок

**Шов сделан ровно как договаривались.** Из `engine.js` вынесено только чтение `data/` — в `src/engine-data.js`. Тела `rank`, `present` и `checkRedflags` не тронуты, включая отступы, чтобы это было видно в истории. Файл обёрнут так, что исполняется и в Node, и в браузере: различается только источник данных. `npm test` гоняет ровно тот модуль, который загружает страница раздела; отдельной браузерной версии ранжирования нет.

Данные едут порциями по разделу: сам раздел, его состояния, только его вопросы (9–29 из 138) и правила тревоги, отфильтрованные по зоне. Самый большой файл — 36 КБ. Грузится по нажатию кнопки, а не при открытии страницы.

### Выбор следующего вопроса

Базой он не задан, поэтому написан заново и покрыт отдельным прогоном (см. ниже). Критерий: **может ли ответ сменить первое место.** Вопрос, который ни при каком ответе ничего не меняет, — потраченный шаг.

Прогон по виньеткам поймал две ошибки, которые иначе уехали бы в продакшен незамеченными:

1. **Слепота к редкому.** Если разводить только нынешних лидеров, редкое состояние стоит внизу по базовой частоте, в набор не попадает — и его патогномоничный признак не спрашивают никогда. Опухоль поджелудочной начинает четырнадцатой из пятнадцати, а «желтуха» весит у неё +6: спроси — и она первая, не спроси — не всплывёт. Теперь в набор входят все живые состояния «редко, но важно не пропустить».
2. **Молчащий слой безопасности.** Оптимизируя порядок статей, селектор перестал спрашивать про ригидность затылка и холодный пот: тревог терялось 23 из 252. Вопрос, приближающий срабатывание правила, теперь ценится наравне с вопросом, меняющим первое место. Отдельно чинилось условие «не хватает только этого ответа»: правилу «длительность плюс потеря веса» в начале не хватает обоих, надбавку не получал ни один из двух вопросов, и правило не срабатывало никогда.

`src/questions-sex.json` — вопросы, которые нельзя задавать человеку не того пола. Список решён вручную: из базы он не выводится, потому что у «последней менструации» веса стоят и у цистита, и у СРК, и у анемии — формально вопрос различает живых кандидатов и у мужчины. Сборка проверяет, что все перечисленные вопросы существуют.

### Что проверено

`npm test` — два прогона. Первый подаёт ответы пачкой: 252 из 252. Второй проигрывает те же случаи через селектор: спрашивает он, отвечает прогон — ответом виньетки, если он в ней есть, и «не знаю», если нет.

| | |
|---|---|
| Тревог упущено диалогом | **0** — порог |
| Ожидаемое состояние вне видимой части | **0** из 252 — порог |
| Ожидаемое в первой тройке | 244 из 252 — справочно |
| Ожидаемое первым | 228 из 252 — справочно |
| Вопросов задано в среднем | 9,6 из 10 |

**Порог — на тревогах, и он нулевой.** Тревога, сработавшая при полной подаче и не сработавшая в диалоге, означает: ответы у человека были, справочник их не спросил и промолчал. Это дефект с именем, а не статистика. Так терялись две:

- `rf.painsoftbelly` — ишемия кишечника (мягкий живот, не находит места, внезапное начало). Диалог спросил только первое из трёх;
- `rf.hardnodes` — лейкоз (плотные узлы плюс больше двух недель). Не спросил ни одного из двух.

Причина общая: надбавка живому правилу делилась на число недостающих ответов, и правило из трёх условий получало 50 против 100 за возможную смену первого места — то есть проигрывало всегда. Теперь надбавка убывает линейно (150 минус 25 за каждый недостающий ответ), и обе тревоги срабатывают.

**Второй порог — видимость, а не вершина.** Человек читает список, а не одну строку, поэтому меряем, попало ли ожидаемое состояние в то, что вернул `present()`. Попадает во всех 252 случаях, в первой тройке — в 244. Все 24 расхождения вершины безобидны: ожидаемое остаётся видимым в каждом. Цена нулевых потерь по тревогам — вершина 228 вместо 242, и по видимой части она не стоила ничего.

Сам остров проверен в headless-браузере на собранной странице: диалог доходит от кнопки до выдачи, тревога поднимается после ответа, а не в конце, ссылки ведут на постоянные адреса статей, адрес страницы не меняется, `localStorage` и `sessionStorage` пусты, кук нет. Вопрос про менструацию появляется только у женщины.

## Силуэт и пол

Силуэт — **вид, а не утверждение о человеке**, поэтому он не убирает разделы никогда. `sexOnly` у участка влияет только на отрисовку. Считано: скрытие участков с чужим `sexOnly` стоило бы двух разделов из 110 на мужском силуэте — «уплотнение в молочной железе» и «боль в молочной железе», где лежат гинекомастия с `sexOnly: "m"` и рак молочной железы без ограничения по полу. Других якорей у этих разделов нет. Участок `pelv.genital` вообще без `sexOnly`: и «выделения», и «мошонка» показываются на обоих силуэтах, и так и должно быть.

Фигура обязана брать участки из `subzonesForSilhouette()`, а не фильтровать сама. Сборка проверяет: 110 разделов достижимы с каждого из двух силуэтов.

**Пол спрашивается один раз — в уточнении.** У фигуры это переключатель картинки, как «спереди / сзади»: его некуда сохранять и незачем передавать. Пол как ответ нужен только движку (`sexOnly` исключает 25 статей из 307). Донести его с фигуры можно было бы только через адрес или хранилище — то и другое запрещено, а страницы перезагружаются целиком, память между ними не живёт.

## Указатель областей и фигура (этапы 2 и 4)

Указатель строится по 10 зонам из `syndromes-map.json`: голова 19 разделов, живот 18, грудь 12, таз 11, общее 10, ноги 10, шея 9, спина 8, кожа 7, руки 6. Внутри области разделы группируются по 52 участкам из `anatomy.json`. Все 110 разделов достижимы, висячих ссылок нет — проверено.

Отдельный вход `/zhaloby/` — `symptom.list` с `noAnchor: true`: 14 разделов для жалоб, которые нельзя показать пальцем. Из списка они обязаны быть доступны, а не только с фигуры.

Фигура: все 52 участка пересчитываются формулой калибровки, а не вбиваются руками, как в прототипе. Четыре числа на картинку. Правило сторон — в CLAUDE.md, проверяется `tools/check-anatomy.js`.

Мелкие участки на общем виде пальцем не берутся не по вкусу, а по арифметике: висок при ширине фигуры 320 px — это 16×23 CSS-пикселя против нормы 44×44. Поэтому на общем виде кликабельны только зоны, участки — исключительно в крупном плане.

```
npm run build        стороны тела → сборка → линт формулировок
```

Сборка останавливается, а не предупреждает, если:

- участок со стороной тела после преобразования вида попал не на ту половину экрана;
- слаг занят дважды или не выводится из id;
- раздел ссылается на несуществующую статью;
- в `questions-sex.json` попал вопрос, которого нет в базе;
- внутренняя ссылка ведёт на несобранную страницу (сейчас 4547 ссылок, битых нет);
- скрипт оказался на странице, которой он не разрешён; код встроен в разметку вместо своего файла; адрес скрипта ведёт на чужой домен. Список страниц со скриптом ведётся явно и растёт только осознанно — сейчас в нём один `/ukazatel/`;
- сработал линт формулировок.

### Линт формулировок: два уровня, и это принципиально

**Жёсткий** — по всему собранному тексту, включая статьи: проценты, «у вас», дозы, «пройдите тест», перенос рисков на читателя. Нигде и ни при каких условиях.

**Мягкий** — только по строкам, которые пишет сайт: `title`, `description` и `src/site/text.js`. Тексты статей приходят из замороженной базы и под мягкий запрет не попадают: в `data/` 52 вхождения «причин», 23 «препарат», 22 «лечен» — и все правомерные, там речь о болезни, а не о читателе («проходит после смены препарата», «без лечения смертельно»). Наивный чёрный список дал бы около 120 ложных срабатываний, и линт отключили бы на второй неделе.

Исключения — в `tools/lint-allow.json`, каждое с причиной. Новое совпадение роняет сборку.
